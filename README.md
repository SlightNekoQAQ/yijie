# 弈界 (Yijie)

完全离线的 Android 混合象棋实验版。一个棋盘决定双方的初始位置，两名玩家分别选择中国象棋或国际象棋走法；每一方在局内可独立切换真人或 AI。支持双人同机、单人对 AI、AI 对 AI 观战、暂停、悔棋、翻转、走棋音效、落子动画、被拒绝走法提示、走棋记录和本地自动存档。双方都由玩家控制时，上侧棋子会朝向坐在对面的玩家；翻转棋盘时朝向随座位转换，人机对局保持全部棋子从手机这一侧正向阅读。

## 安装包构建

将本目录推送到 GitHub，在 Actions 中运行 `Android APK`，从运行页面的 `yijie-debug-apk` 下载 `app-debug.apk`。推送到 `main` 也会触发构建。该 APK 是可直接侧载的调试安装包，不是应用商店发布版。Actions 使用 JDK 17、Gradle 8.10.2、Android SDK 35；手机无需安装 Android SDK。仓库密钥 `YIJIE_KEYSTORE_BASE64` 和 `YIJIE_STORE_PASSWORD` 用于固定签名，私钥不在仓库中；构建未来版本需保留这两个密钥。密钥备份保存在本机 `~/.aether/yijie-signing/`（目录应保持私有）。

**从 0.1.0 升级时注意：**初版使用临时调试签名，新版可能无法覆盖安装。若 Android 提示签名冲突，需要先卸载旧版再安装新版本；卸载会清除旧版的本地棋局。0.2.0 起使用固定签名，后续版本（包括 0.3.0）可正常覆盖安装。

本机有 Node.js 时，运行 `node --test tests/*.test.js` 检验规则。

## 规则来源与适用范围

- 国际象棋走法参考 [FIDE《国际象棋规则》](https://handbook.fide.com/chapter/E012023) 第 3 章，尤其是 3.1.3（受牵制的棋子仍攻击格子）、3.7（兵、吃过路兵、升变）、3.8（王车易位）、3.9（将军及禁止暴露己方王）。标准国际象棋的合法着还与开源 `chess.js` 对照了 40 局随机局面。
- 中国象棋规则参考[世界象棋联合会《世界象棋规则》](https://www.wxf-xiangqi.org/images/wxf-rules/2018_World_Xiangqi_Rules_Chinese_2018.pdf)及其[官方介绍](https://www.wxf-xiangqi.org/index.php?option=com_content&view=article&id=271&Itemid=290&lang=cn)。九宫、河界、马腿、象眼、炮架与兵过河按中式走法实现。
- 两套权威规则都**没有定义跨体系对局**；九路西式阵容、八路中式九宫（四列 × 三行）、中式将与西式王照面时的攻击、混合局禁止易位，均为《弈界》自定规则。用户指定的“无合法着判负”也取代了国际象棋原本的逼和判和；三次重复判和作为防止无限循环的统一约定。目前未实现世界象棋规则中的长将/长捉裁决。

## 当前玩法规则

- 中式棋盘为 9×10 交点；西式棋盘为 8×8 格。双方使用该棋盘对应的初始位置，再由各自走法决定棋子映射。
- 9×10：中式方保留标准车马象士将炮兵。西式方的车、马、象、王、兵按西式走法；两枚炮和一个士位空出。默认「让车试验」还空出 c 路象位和 i 路车位（x=8），即不放后且少一车。可选「撤后试验」恢复双车但不放后，或「原始实验」在 c 路放一枚西式后。原 d 路开局直攻九宫可速胜，因此单后方案移到 c 路。现有存档保留其原始阵容，新预设只影响新对局。**三种方案都不保证公平**。
- 8×8：西式方为标准国际象棋阵容。中式方的车、马、象、王、兵分别映射为车、马、象、将、兵；后的位置是一个士，没有炮。这是独立实验预设，并非标准中国象棋阵容。
- 中式将/士局限九宫，中式象不能过河，马蹩腿，象塞象眼，炮隔一子吃，兵过河可以横走。8×8 中式九宫是居中的四列 × 三行；河界在两方中间。
- 西式兵首步可走两格、斜吃、吃过路兵，到底线可选后/车/象/马升变。仅双方均按西式规则且在 8×8 棋盘上可以王车易位。
- 走棋不能使自己的王/将被攻击；将死判胜。无合法走法即使未被将军也判负。王/将不可直接被吃。三次重复局面判和。
- 相同棋盘不同走法及中式走法落在西式棋盘上均为实验规则。混合玩法尚无可靠平衡性数据。

## AI 状态

当前 AI 基于双方共享的合法着判定器。吃子和失子按照各自棋制的剩余材料差计分：西式兵 1、马/象 3、车 5、后 9；中式兵 1、士/象 2、马 4、炮 4.5、车 9（王/将不能吃），过河兵另有位置分。开局搜索两层，剩余不超过 12 子时尝试三层，不超过 7 子时尝试四层；额外搜索限时 650 毫秒，超时沿用上一层完整结果。终局、将军与重复局面影响选着。它**不是**皮卡鱼或 Stockfish，棋力仍弱；搜索在 WebView 主线程运行，复杂局面仍可能短暂卡顿。后续计划在标准局分别接入 Pikafish 与 Stockfish 的离线 Android 二进制，并在混合局升级共享搜索与局面评估。引擎接入时需要同时核对授权、源码提供和架构兼容性；现有 APK 不包含这些外部引擎或网络功能。固定种子的 12 局自对弈（每局最多 110 手）中，原双车撤后预设为西式 8 胜、中式 3 胜、1 和；让一车预设为西式 3 胜、中式 4 胜、1 和、4 未完。样本太小，既不能证明公平，也不能保证更长的必胜局面一定能被四层搜索发现。

## 目录

- `app/src/main/assets/rules.js`：共用走法、胜负判定、基础 AI
- `app/src/main/assets/app.js`、`style.css`、`index.html`：离线对局界面
- `app/src/main/java/com/yijie/game/MainActivity.java`：Android WebView 容器
- `tests/rules.test.js`：规则回归测试
- `.github/workflows/android.yml`：CI 构建并上传 APK
